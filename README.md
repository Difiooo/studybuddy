# StudyBuddy — AI Flashcard Generator

## Project brief

Paste your lecture or reading notes and get back 5–8 structured
question/answer flashcards, generated by the Claude API. It's for students
(myself included) who have a pile of notes and want to test their own
understanding without manually writing flashcards by hand. I chose this over
a chatbot because it solves an actual step in studying — turning passive
notes into active recall — rather than being a text box that talks back.

## Setup & run locally

```bash
npm install
npm run dev        # http://localhost:5173
```

The frontend runs fine standalone, but flashcard generation needs the
Netlify function running too. To test the function locally:

```bash
npm install -g netlify-cli
netlify dev         # proxies the Vite server + the function together
```

You'll need an Anthropic API key (free at console.anthropic.com) set as
`ANTHROPIC_API_KEY` in a local `.env` file (never committed — see
`.gitignore`) or exported in your shell before running `netlify dev`.

```bash
npm test            # run the Vitest suite
```

## Architecture

```
src/
  App.tsx                 — page shell, landmarks (header/main/footer)
  components/
    NotesForm.tsx          — validated textarea, calls the API client,
                             owns loading/error/success state
    FlashcardList.tsx       — renders results as native <details> elements
  lib/api.ts               — typed fetch wrapper around the Netlify function
                             (the only place the frontend touches the network)
netlify/functions/
  generate-flashcards.js    — validates input, calls the Claude API with a
                             structured-output prompt, validates the model's
                             JSON before returning it to the frontend
```

Data flow: `NotesForm` → `generateFlashcards()` (`src/lib/api.ts`) →
`POST /.netlify/functions/generate-flashcards` → Claude API → validated JSON
→ back to `NotesForm` → `FlashcardList`.

## AI integration — how and why

The Netlify function (`netlify/functions/generate-flashcards.js`) sends the
user's notes to Claude (`claude-3-5-haiku-20241022`) with a system prompt
that asks for **structured JSON only** — `{"flashcards": [{"question",
"answer"}, ...]}` — not free-form prose. This matters for two reasons:

1. The frontend needs a predictable shape to render, not something it has to
   parse out of a paragraph.
2. It lets the function validate the model's own output before trusting it —
   if Claude returns malformed JSON, an empty array, or cards missing a
   question/answer, the function catches that server-side and returns a
   clear error instead of forwarding garbage to the UI.

The API key never reaches the browser — it's a server-side environment
variable used only inside the Netlify function.

## Known limitations & future improvements

- **No persistence.** Flashcards disappear on refresh; there's no way to
  save a set and come back to it. Next step would be local storage or a
  lightweight backend (e.g. Supabase) to save sets per user.
- **No spaced repetition.** It generates cards but doesn't schedule review —
  the "study" part beyond generation is still manual.
- **Single-shot generation.** If the notes are messy or off-topic, the only
  recourse is editing the notes and resubmitting; there's no "regenerate
  card #3" or manual editing of individual cards yet.
- **English-only tuning.** The prompt hasn't been tested against non-English
  notes; results in other languages are untested.

## Testing evidence

`npm test` runs 9 tests across 2 files (Vitest + React Testing Library),
covering:

- Empty and too-short input rejected client-side, API never called
- Loading state exposes `role="status"` + `aria-live="polite"`, and the
  submit button disables while in flight
- Successful response renders flashcards
- Server-returned error message displayed via `role="alert"`
- Network failure (fetch throwing) shown as a generic, honest error
- Flashcard list exposes an accessible list name for screen readers

All queries use role/label, not test IDs — renaming a class name doesn't
break these tests.

## Deployment & operation

See `DEPLOYMENT_CHECKLIST.md`.

**Failure modes and how they're handled:**

| Failure | User sees |
|---|---|
| Empty/too-short notes | Inline `role="alert"` error, no request sent |
| Notes too long | Inline `role="alert"` error, no request sent |
| Missing `ANTHROPIC_API_KEY` on the server | 500 with an explicit message (not a bare crash) |
| Claude API down / rate-limited | 502/429 surfaced to the user as a plain-language retry message |
| Claude returns malformed JSON | Function catches the parse failure, returns a clear error instead of forwarding garbage |
| Network failure in the browser | Caught in `lib/api.ts`, shown as a generic "something went wrong, try again" |

**Rollback plan:** Netlify keeps every previous deploy. If a bad deploy ships,
go to the site's **Deploys** tab and click **Publish deploy** on the last
known-good build — no redeploy from source needed.
